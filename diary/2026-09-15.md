### Problems solved

- **`/api/map/assets` returned nothing useful on the VPS.** Four causes in
  a row:

  1. `.env` had no `KB_DB_*` at all — it was written on Sep 11 when
     `infra/.env.example` still said kb was "unused until the Map/Ask
     slices". Django fell back to `localhost`, which inside a container is
     the container.
  2. No `pg_hba.conf` rule for the new role from the compose network. The
     container connects **to** `172.17.0.1` but arrives **from**
     `172.26.0.2`, the geo-portal compose network. Rule added for
     `172.16.0.0/12`.
  3. The `GRANT SELECT` statements had been run against the wrong
     database. `\connect gobase` in a pasted block is easy to miss; use
     `psql -d gobase -c ...` so the database cannot be implicit.
  4. **rustfs does not listen on the Docker bridge.** It publishes only on
     `127.0.0.1:9000` and `100.71.238.58:9000`, so `host.docker.internal`
     timed out. Postgres works there because it *does* listen on
     `172.17.0.1`. `LAKE_S3_ENDPOINT` now points at the Tailscale address.

  Verified end to end: 22 active assets, the role refuses writes, and three
  assets read real GeoParquet out of rustfs including the 5000 cap firing.

- **The map drew nothing, in five layers, each hiding the next.** All
  silent, because the failing request is made by the worker loader and not
  by the map, so nothing surfaces as a map error:

  1. Vite pre-bundling broke MapLibre's worker URL in development.
  2. The production build never emitted the worker at all — MapLibre picks
     its filename at runtime, which no bundler can follow.
  3. nginx's SPA fallback answered the worker request with `index.html` —
     a 200 that is not JavaScript.
  4. `.mjs` has no entry in nginx's stock `mime.types`, so the file went
     out as `application/octet-stream` and the browser refused to execute
     a module worker. **The refusal is asynchronous, so MapLibre's
     documented fallback to a classic worker never fires.**
  5. `?url` emitted the worker alone. It imports
     `./maplibre-gl-shared.mjs`, which was never emitted, so the worker
     404'd on its own dependency. The browser reports this as a bare
     `error` event with no message — indistinguishable from layer 4.

  Fix: `?worker&url`, which builds it as an entry point and bundles its
  imports. Self-contained, 476K, and lands as `.js`.

### Decisions

- **Keep the nginx `.mjs` mapping** even though the worker is now `.js`.
  It is correct for any future `.mjs` and documents the trap.
- **`default_type` in a regex location, never a `types` block.** A `types`
  block inside `server` REPLACES the inherited mime map: the first attempt
  turned every `.js` and `.css` into `application/octet-stream` for about
  a minute. A regex location also outranks the `/assets/` prefix, so the
  cache headers are repeated inside it.

### Open threads

- **`LAKE_S3_ENDPOINT=100.71.238.58:9000` is a Tailscale address.** If it
  changes, `/data` breaks with no clue why. Sturdier: publish rustfs on
  `172.17.0.1:9000`, or attach the portal to `rustfs_default` and use
  `rustfs:9000` — the latter needs a change to `docker-compose.prod.yml`,
  which is CI-managed.
- **`deploy.sh` reported success through all of this.** Its health check
  probes `/api/health/` only, which touches no database. Green means "the
  process started", not "the app works".
- **`main` has never deployed.** Only a `development` environment exists,
  and production's `.env` will have the same Sep-11-era gaps.
- **Not verified in a browser yet**: the deployed map drawing vectors.
  `25f212f` was verified as a worker that loads, not as a map that draws.
- **`/assets/` is served `immutable` for a year.** A content type that
  changes while content does not is invisible to content hashing, so a
  browser that fetched the broken worker keeps it until its cache is
  cleared. That cost a round of debugging.
- **71 tests passed through every one of the five layers.** Nothing in
  this repo loads a real map or inspects a real build. Two cheap checks
  would have caught three layers with no browser: assert `dist/assets/`
  contains a worker, and assert that worker has no unresolved imports.
