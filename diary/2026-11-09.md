## 21:45 — Ask citations: markers become numbered marks, chips only for what was cited

Tickets: none — from `HANDOFF-ask-citations.md` (the gobase-agent session's
note, now deleted). Branch `Week_12-dev`, uncommitted.

### What changed
- `ChatReferenceSerializer` passes four more optional fields: `handle`
  (checked against the agent's pattern `^[AP][1-9][0-9]{0,4}$`), `cited`,
  `name`, `data_type`. `openapi.yaml` and the Orval client regenerated.
  Contract note in `context/integrations/agent.md`.
- `features/ask/references.ts`: `citationMarks(text, references)` numbers
  the `[A1]` markers by first appearance; `groupReferences(references,
  text)` keeps only cited references and sorts chips by that number.
- `AnswerText` renders each known marker as `CitationMark`, a small
  numbered inline button that opens the asset. Other brackets stay text.
- `CitationChip` shows the number, and renders from the reference's `name`
  and `data_type`; the catalog lookup is only the fallback (the query is
  disabled when the name is known).
- Tests: backend 524 (5 new), frontend 246 (7 new). Lint and build clean.
  `specs/ask.md` and `context/ui-registry.md` updated.
- Checked end to end with the real agent on `:8020` through the gateway:
  six references with handles, names, types; `cited` on each at `done` and
  in the stored turn. Not checked in a browser (no browser tool here).

### Decisions
- A reference is cited when its handle appears as a marker in the text, or
  `cited: true`; `cited: false` hides it; no handle and no flag shows it (an
  older agent still works). The marker rule gives chips while streaming and
  after an `error`, which never brings `done`. Rejected: nothing until
  `done`; all references muted until `done`.
- Marks are renumbered 1, 2, 3 per answer, chips numbered the same.
  Rejected: showing the handle itself (stable across turns, but jargon),
  the asset name inline (long).
- `name`/`data_type` come from the agent and are used directly. Fewer
  requests, no skeleton flash.

### Problems solved
- `POST .../turns` gave 500 "Event loop is closed" under `manage.py
  runserver` → runserver is WSGI; the relay streams → serve with
  `.venv/bin/uvicorn config.asgi:application --port 8000` (agent.md says so).
- `pkill -f "<pattern>"; exec uvicorn …` in one command killed itself → the
  pattern matched the new shell's own command line → use `[r]` bracket trick.
