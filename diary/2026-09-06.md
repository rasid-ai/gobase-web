# 2026-09-06 (second session) — Landing & sign-in: first vertical slice

**Tickets / requirement IDs touched:** HLR-001, 002, 003, 004, 005, 007
(backend only), 008, 027

**What changed:** The repo went from documentation-only to a running
application. `/architect` first, decisions confirmed before any code.

Backend (`backend/`): Django 5.2 + DRF, `apps/accounts` with `UserProfile`
(admin|viewer) inlined into stock Django admin, and five endpoints under
`/api/auth/` — login, refresh, logout, me, change-password. Access token in
the response body, refresh token in an httpOnly `SameSite=Lax` cookie
scoped to `Path=/api/auth`. Rotation with blacklist-after-rotation, so a
replayed cookie is genuinely rejected. DRF's default permission is
`IsAuthenticated`, which is what makes HLR-001 structural rather than
per-view. `config/db_router.py` refuses migrations and writes against the
`kb` alias — ADR-002 made mechanical instead of conventional.
`openapi.yaml` exported via drf-spectacular. 17 pytest tests, each tagged
`@pytest.mark.hlr(...)`.

Frontend (`frontend/`): Vite 8 + React 19 + TS, Tailwind v4 consuming the
existing `tokens.css` untouched, Orval-generated client, TanStack Query,
RHF + Zod. Landing page ported from the Claude Design mockup; sign-in built
in the same visual language. 16 Vitest tests.

**Decisions taken (no ADR — scope choices with no competing alternatives,
same precedent as this morning's amendment):**
- **Auth-conditional route tree.** `/` is the landing page for a visitor
  and the Map workspace for a signed-in user, which is what ui-rules.md
  asks for in two places. No doc amendment needed.
- **Endpoint surface widened** to include refresh, logout and
  change-password. Refresh is required by HLR-003 at all; without logout
  there is no way to leave a session. Recorded in architecture.md.
- **Mono micro-labels are allowed on the pre-auth pages** and nowhere else.
  The mockup uses them, rasid.ai uses them, and design-system.md forbade
  them; the exception is now written into design-system.md rather than left
  as a silent contradiction.
- **Dev is same-origin.** Vite proxies `/api` to Django, so the refresh
  cookie behaves in development exactly as it does behind nginx, and CORS
  is never configured at all.

**What broke:**
- Orval 8's fetch mutator is `(url, init)` returning
  `{data, status, headers}` discriminated on status — not the axios-shaped
  `({url, method, data})` throwing client I first wrote. Rewrote
  `http-client.ts` and both call sites against the real contract.
- **Sign-out landed on the landing page, not the login screen** — caught by
  the HLR-004 test. With a conditional route tree, ending a session at `/`
  renders the anon `/`, which is the landing page; the spec says login
  screen. Fixed by distinguishing an expired session from a deliberate
  sign-out (`sessionExpired` in the auth context). Worth remembering: a
  conditional route tree makes "where do I land" depend on the current URL,
  so every exit path needs stating explicitly.
- **Prettier reformatted `tokens.css`**, stripping the trailing zeros that
  document the tonal ladder (values numerically identical). Restored from
  the tarball snapshot and added to `.prettierignore` with a note. The
  design-token file is data, not source — formatters must leave it alone.
- Node on this machine was 18; Tailwind v4 and Vite need 20+. Installed nvm
  + Node 22.23.2 + pnpm 10.15.0. `.nvmrc` pins it.

**Verified:** 17 backend + 16 frontend tests green; ruff, eslint, prettier
and `pnpm build` clean. Real-browser walk over CDP: login → shell, full
reload → still signed in, `/runs` deep link while signed out renders the
sign-in screen byte-identically, sign out → sign-in. In the browser,
`localStorage`, `sessionStorage` and `document.cookie` are all empty while
signed in — the access token is unreachable from JS and the refresh cookie
is genuinely httpOnly. Landing checked in both themes.
