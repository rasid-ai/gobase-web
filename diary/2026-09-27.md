# 2026-09-27

## 14:44 — Datasets and metadata search on both pages, a draw-area crash, basemap options

Tickets: none — asked for in session. Branch `Week_8`.

### What changed

- **One catalog API answers both pages** (docs/adr/016). `/api/catalog/assets`
  gains `dataset`, a point (`lon`, `lat`) or drawn `area` as the place, and
  `q` over the asset's catalog text. `/api/catalog/datasets` is new.
  `/api/map/assets` is gone; the Atlas pane calls the catalog. The asset
  detail gains `name`.
- **Assets page:** a Datasets / Assets switch. Datasets lists datasets by
  readable label, opens to their assets. **Atlas pane:** datasets → files
  (search, data type toggle) → detail; the detail expands to show
  structured metadata as tables.
- New components: `ui/Segmented`, `MetadataValue`, `PageBoundary` (wraps
  each page in the shell, keyed by path).
- Docs: ADR-016, specs/assets.md, specs/map.md, kb.md (the `dataset`
  column, the 2026-09-27 snapshot, the deploy rule), architecture.md,
  ui-rules.md, ui-registry.md.

### Decisions

All in ADR-016; the ones a future session will trip over:

- **Deploy only together with gobase `Week_8`.** The portal reads
  `assets.dataset` with no fallback; production does not have it yet.
- Search is an exact match, over tag **values** not keys, with fields
  joined by `\x1f` so a search cannot bridge two of them.
- The mode and the open dataset are not in the URL (ADR-011's rule), so
  Back leaves the Assets page rather than stepping out of a dataset.
- The Atlas data type toggle is one choice (All, or one type); the Assets
  page keeps its checkboxes. The Assets page title stays "Assets" in both
  modes.

### Problems solved

- **The detail showed `columns`, `bands`, `tags` as a line of JSON** →
  Django sets psycopg 3 to return `json`/`jsonb` as text, so a raw cursor
  on `kb` got strings → `kb._rows` decodes JSON columns by type id. Now
  in kb.md.
- **Blank app after drawing an area, then going to Assets** (`reading
  'setData'`) → react-map-gl removes the map before `DrawArea`'s cleanup,
  and terra-draw's `stop()` writes to sources that are gone; an error
  during unmount takes down the whole React root → `DrawArea` skips
  `stop()` once the map has fired `remove`. There since ADR-014.
  `PageBoundary` could not have caught it.

### Open threads

- **Basemap undecided.** OSM Standard raster is "not nice on the eye".
  Compared: OpenFreeMap Positron + Dark (no key, free) against Esri Light /
  Dark Gray as ChatAEC uses (key kept on the backend via basemap session
  tokens, paid past the free tier, settles ADR-011's open Esri-terms
  question). Whichever is chosen is ADR-017. Either way the OSM credit is
  still partly hidden behind the right pane.
- Basemap caching needs nothing: the browser keeps OSM tiles per their
  headers (measured 45 of 48 from cache on returning to Atlas).
- Leaving `/map` rebuilds the map: view, drawn area and drawn layers are
  lost. Keeping it alive across pages is not designed.
- The search text is built per request; fine at 54 assets, needs a stored
  column (data platform) at tens of thousands.
- ChatAEC's public JavaScript appears to carry an ArcGIS key; tell
  whoever runs it.
- Carried over: the count-first fix for country zoom (2026-09-24); rotate
  the ArcGIS key (2026-09-18); `LAKE_MAX_FEATURES` in local `backend/.env`.
