## What changed

**Backend.** `config/health.py` + `config/tests/test_health.py`:
`GET /api/health/`, public, `SELECT 1` against `portal` only, 503 when it
fails. `kb` is deliberately never probed — a knowledge base outage must
not fail a portal deploy. WhiteNoise added, `STATIC_URL` moved to
`/django-static/`, `STORAGES` set to the compressed manifest backend,
`SESSION_COOKIE_SECURE`/`CSRF_COOKIE_SECURE` tied to `not DEBUG`, plus
`SECURE_PROXY_SSL_HEADER` and `DJANGO_CSRF_TRUSTED_ORIGINS`. New pins:
whitenoise 6.12.0, gunicorn 23.0.0, uvicorn[standard] 0.41.0. The `api`
fixture moved to `backend/conftest.py`; `testpaths` widened to
`["apps", "config"]`.

**Images.** `backend/Dockerfile` (python:3.12-slim, collectstatic at
build, non-root, gunicorn + UvicornWorker) with `entrypoint.sh` running
`migrate` before exec'ing the command. `frontend/Dockerfile` staged
deps → dev → build → production, with `production` last so a plain
`docker build` gets the shipping image; `frontend/nginx.conf` serves the
SPA with a fallback and immutable asset caching. `packageManager:
pnpm@10.15.0` added so corepack, CI and the image agree.

**Infra.** `infra/docker-compose.prod.yml`, `infra/deploy.sh` (Rainbow's,
plus a `GHCR_OWNER` guard and backend logs on health-check failure),
`infra/.env.example`, `infra/README.md` (host setup end to end), and a
root `docker-compose.dev.yml` building from the same Dockerfiles.

**CI.** `.github/workflows/ci.yml` — backend (ruff + pytest against a
Postgres 16 service), frontend (lint/test/build), and a contract job that
regenerates `openapi.yaml` and the Orval client and fails on drift.
`.github/workflows/deploy.yml` — checks via `workflow_call`, matrix build
of both images to GHCR, then scp `infra/` + run `deploy.sh` over plain
openssh, with the environment selected from the branch.

Created the local `dev` branch. Not pushed.

## Decisions

All recorded in the plan; two went to ADRs or are worth repeating here.

- **Django admin is served in production** — ADR-007. Role assignment has
  no other UI, and the alternative (SSH + `manage.py`) trades a narrow
  authenticated surface for a much broader one. Brought
  `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE` and two extra nginx
  routes with it.
- **The health endpoint is in the contract**, not `exclude=True`. Orval
  generates a hook nothing calls; that is cheaper than a live endpoint
  the contract does not describe.
- **CI verifies `openapi.yaml`, never commits it.** A bot commit on a
  protected branch walks straight past Gate C.
- **`deploy.yml` re-runs `ci.yml`** rather than trusting the PR gate, so
  a direct push to `dev` is still checked.
- **Moving image tags are per branch** (`latest` only from `main`, `dev`
  from `dev`). A shared `latest` would mean a manual `compose up` on the
  production host quietly starting a development build.
- **Plain openssh over `appleboy/*`**, with `VPS_SSH_KNOWN_HOSTS` pinned
  rather than `ssh-keyscan`. The step holds the production key; trusting
  whatever answers first hands a deploy to a man in the middle.
- **Rejected: a Postgres container for local dev.** Keeping the host
  Postgres means dev mirrors prod's native-Postgres topology, at the cost
  of a one-time TCP/password setup on the developer machine.

## Problems solved

- **`docker build` of the frontend ran past ten minutes** → the pnpm
  install layer on alpine, not a hang. It finished at ~14 min cold and is
  cached afterwards; CI uses `type=gha` scoped per component so this is a
  first-run cost only.
- **A dev-compose smoke test reported a healthy Vite on 5173 that was not
  the container** → a dev server from an earlier session already held the
  port, so `curl` hit the host. Docker had in fact failed to bind and
  said so. Re-tested on 5199 through a compose override. Worth
  remembering: a port check proves something answers, not that *your*
  thing answers.
