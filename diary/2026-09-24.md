# 2026-09-24

## 20:13 — Pruning by the covering column, a polygon draw mode, and a page written by DuckDB

Tickets: GP-1 (epic Map), GP-6, GP-7. Branch `Week_8`, off `origin/dev` after
PR #9 merged `PostDemoFixes`. Local only; nothing deployed.

### What changed

- **The area filter prunes by the covering `bbox` column** (handoff from the
  gobase session). Silver GeoParquet now carries `bbox STRUCT(xmin..)`, Hilbert
  order, 25k-row groups. `lake.read_vector_features` tests it before the
  geometry; `bbox` is excluded from properties. docs/adr/013.
- **Draw-area mode is back, as a polygon.** terra-draw + its MapLibre adapter
  (both MIT, pinned). The panel lists assets overlapping the polygon
  (`GET /api/map/assets?area=` WKT) and drawn layers are read for the polygon,
  exactly (`ST_Intersects`), not for the view. `AreaField` validates the
  polygon. docs/adr/014.
- **The features endpoint writes its own body.** DuckDB builds the page's
  GeoJSON in the query; the view writes it unparsed, gzips at level 1, and sets
  an ETag with `private, no-cache` — a matching ETag is a 304 without reading
  the lake. The client never treats feature pages as stale. docs/adr/015.
- **Page size 10,000 on both sides** (`LAKE_PAGE_SIZE`, `PAGE_SIZE`), and
  **`PAGE_BUDGET` 6** — up to 60,000 features per layer per window.
- 10K-building page over Beirut: 731–946 ms and 5.2 MB before, 273 ms and
  1.29 MB now; a revalidated reload is a 304 in ~2 ms.

### Decisions

All recorded in ADRs 013–015; the ones a future session will trip over:

- `FEATURES_FORMAT` in `backend/apps/map/views.py` must be bumped whenever the
  same request could get a different body. Forgetting leaves browsers serving
  the old body behind a matching ETag.
- ETag caching is only safe because assets are content-addressed: changed
  content gets a new `asset_id` (`assets.content_hash`). Verified against the
  12 files rewritten today — all got new ids.
- Gzip on the features endpoint only, not site-wide: Django's middleware also
  compresses streaming responses and would stall the Ask slice's SSE.
- Vector tiles built on request are not the fast path: 10.6 s of CPU for a
  z13 view of Beirut. Pre-generated tiles (PMTiles, data platform) would be.
  Chose to keep GeoJSON for now.

### Problems solved

- **"The draw-area mode was temporarily moved out"** → it was never built: four
  lines (`0aaa6c8`), removed in `ca56708`. Built from scratch.
- **A bowtie polygon was refused as "flat"** → zero signed area was used to
  mean flat, and a symmetric bowtie's lobes cancel. Flatness is now tested
  directly. `AreaField` agrees with PostGIS `ST_IsValid` on every shape tried.
- **PostGIS and DuckDB both answer a self-intersecting polygon silently** →
  wrong count, no error. `AreaField` is the only guard; the draw tool refuses
  the same shapes at the click.
- **"gunicorn limits the request line to 4094 bytes"** → false here: the
  Dockerfile runs `UvicornWorker`, which parses HTTP itself (a 9.2 KB line
  reached Django). The binding limit is the host nginx's 8 KB default. The
  100-corner cap stays, with that reason.
- **Two existing `<Source>`s stopped compiling after adding terra-draw** → its
  types import `geojson`, which made react-map-gl's `data` prop strict.
  `@types/geojson` is now a direct, pinned dev dependency.
- **`Required module 'pytz' failed to import`** on `boundaries/lebanon.parquet`
  and `healt_sites/lebanon_hxl.parquet` → a zoned timestamp becoming a Python
  `datetime`. Earlier today these were wrongly reported fixed: that check only
  ran `DESCRIBE`, which reads no values. Actually fixed by DuckDB writing the
  JSON — no value leaves DuckDB.
- **Panning back to a window re-downloaded every page** → React Query's default
  `staleTime` is 0. Now `Infinity`; a test covers it.
- **The draw tool could wait forever for the map** → MapLibre's
  `isStyleLoaded()` is also false while tiles load. `DrawArea` waits on the
  map's `onLoad` instead.
- **DuckDB `COLUMNS(...)` inside an expression duplicates the whole
  expression** → use `*COLUMNS(...)` to unpack into arguments.
- **`ST_AsMVT` rejects a tile** → clipping a feature to the tile edge can yield
  a `GEOMETRYCOLLECTION`. Matters only if tiles are built.

### Open threads

- **Nothing from today has been seen in a browser.** Draw mode, the 304s, and
  the budget of 6 are all verified by tests and against the real lake only.
- **Known and deliberately left:** pages arrive in file order, which is now
  location order, so a window over the budget is drawn as a solid region — at
  country zoom 30,000 buildings covered 2.8% of Lebanon. And the fetched window
  is 2.4–3.5× the screen at city zoom. The discussed fix: count a window first
  (~65 ms), then load it whole or not at all; for city zoom, a grid of cells.
  Not chosen yet.
- **Measured, not built:** cutting coordinates to 6 decimals in the GeoJSON
  string halves the bytes on the wire (8.4 → 4.2 MB for all of Beirut).
- Browser cost is the floor for GeoJSON: 1.3–1.9 s to parse and index 63,682
  buildings, with `JSON.parse` on the main thread.
- GP-6 and GP-7 are commented, not closed: the area exists, asking a question
  of it does not.
- Local `backend/.env` still has `LAKE_MAX_FEATURES` (old name, now ignored).
- From 2026-09-18, not revisited: rotate the ArcGIS key.
