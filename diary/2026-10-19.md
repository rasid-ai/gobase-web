# 2026-10-19

## 20:05 — Documents are named after their PDF, and the PDF opens from bronze

Tickets: none — asked for in session. Branch `Week_8`.

### What changed

- **Catalog knows documents** (docs/adr/017). Every catalog read LEFT JOINs
  `doc_documents`; a document is named after `pdf_uri`'s basename, extension
  kept, falling back to the bundle stem. The browse list gains
  `document: {title, pages, pdf} | null`. The PDF's name and title are in
  the search text.
- **`GET /api/catalog/assets/{id}/pdf`** serves the PDF from bronze through
  DuckDB `read_blob` (new `lake.read_blob`), inline, named, with
  `content_hash` as a strong ETag and 304 on revalidation. 404 / 502 / 503
  as the features endpoint. `LakeUnreachable`, `LakeFailed` and `cacheable`
  moved to `apps/map/http.py` so both views share them.
- **Assets page:** a document card shows the PDF name, the parser's title
  under it, the page count instead of "0 B", and an **Open PDF** button that
  opens a new tab first (inside the click) and then points it at a blob of
  the bytes fetched with the session. `fetchWithSession` split out of
  `httpClient`. Failure closes the tab and says so on the card.
- Docs: ADR-017, kb.md (`doc_documents`, the 2026-10-19 snapshot, the
  deploy-together rule), lake.md (bronze, `read_blob`), specs/assets.md,
  ui-registry.md. Contract regenerated.

### Decisions

- PDF filename as the name, not the parser's title (Ali's call; the live
  titles are "1. Introduction" and the like).
- New browser tab, not an in-app viewer (Ali's call).
- No boto3: DuckDB `read_blob` works with the existing lake secret, verified
  against local MinIO. Whole-file; streaming is the upgrade path if PDFs
  ever get large.

### Gotchas

- **`kb` without `doc_documents` now fails every catalog read.** Same
  deploy-together rule as `dataset`.
- A false alarm worth not repeating: `ps aux` on this laptop lists a Frappe
  gunicorn bound to `0.0.0.0:8000`, but it runs inside the `crm_prod_setup`
  Docker containers and never takes the host's port. Django runs on 8000 as
  normal; check with `ss -ltnp`, not `ps`.
- `test_catalog_text.py` runs `_SEARCH_TEXT` for real against temp tables;
  a new joined table has to be created there too.
- Django's `content_disposition_header` quotes an ASCII name plainly and
  only uses `filename*` for non-ASCII.

### Verified

Backend 299 tests, frontend 191, tsc, ruff, prettier. Live (Django on a
spare port): 200 with
358,587 bytes of `%PDF-1.6`, 304 with the ETag, 404 unknown id, 401 no
token; list shows four `.pdf` names with `document` fields; "Beirut" finds
them.

### Next

- Open at a page: `?page=N` → `#page=N` on the object URL; chunks carry
  `page_start`. Lines are not possible (no line data).
- Search documents by meaning (Postgres candidates, then the Lance chunk
  table) and by their dataset's place.

## 21:00 — Semantic mode on the map: find assets by meaning

Tickets: none — asked for in session. Branch `Week_8`.

### What changed

- **`GET /api/catalog/assets/similar?q=&limit=`** (docs/adr/018). The
  question goes to GoDoc's RAG server (`POST {GODOC_URL}/rag/embed`, new
  `apps/catalog/godoc.py`, settings `GODOC_URL` / `GODOC_TIMEOUT_SECONDS`
  with the geocoder's blank-means-503 rule); the catalog ranks `doc_cards`
  by cosine (`kb.similar_assets`, the browse CTE joined to the cards of
  the model the server names). A match is a list row plus `score` and
  `dataset_bbox` (envelope of the dataset's active assets).
- **Map:** fourth mode **Semantic**. `SemanticPane` at the right: question
  box, ranked `AssetRow`s with Open PDF and Dataset extent beneath (each
  only where it can go), the usual detail. The extent is a dashed
  footprint-coloured box, framed, cleared on leaving the mode. The question
  survives a mode switch. `AssetRow` takes `children`; `Failed` and
  `AssetRow` exported; `OpenPdf` moved to its own file; `fakeTab` into the
  test harness.
- Docs: ADR-018, context/integrations/godoc.md (new), kb.md (`doc_cards`),
  specs/map.md, ui-registry.md. Contract regenerated.

### Decisions

- Mode named **Semantic**, question box in the pane (Ali's calls).
- Embedding through GoDoc's existing `/rag/embed`, not a model in the
  portal: same model as the cards, no GPU here, and the backend owns every
  model call (ADR-011).
- Filter the cards on the model the server names; gobase does not, and a
  second model's cards would rank nonsense. Bare question, no bge
  instruction prefix, to match the cards.
- Score in the contract, not on screen (ui-rules). Draw offered on every
  row, as everywhere; a document says "No vector data to draw" when asked.
- Meaning only for now; the place filter is the next feature.

### Gotchas

- **`airports` has no asset with an extent**, and all four cards are in
  it, so Dataset extent is hidden for every live match today.
- A Django started before `GODOC_URL` was in `.env` answers 503 "not
  configured" until restarted — `load_dotenv` does not re-read on reload.
- `ReturnType<typeof useCatalogSimilarAssets>` is `{}`: pass the narrowed
  pieces to a child, not the query object.

### Verified

Backend (catalog) 191 pass, ruff clean; frontend 202, tsc, lint, prettier.
Live on a spare Django: "economic impact of reopening an airport" → the
Rene Mouawad PDF first (0.77); "passenger numbers in 2024" → the 2024
activity sheet first (0.73); embedder `BAAI/bge-small-en-v1.5`.

### Next

- Narrow matches to a place (dataset extent ∩ point/area).
- Chunk-level search (Lance) and open-at-page.
- Restart Django on 8000 so it reads `GODOC_URL`.
